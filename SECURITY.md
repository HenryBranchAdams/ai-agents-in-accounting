# Security

The website and API are read-only. Report executable-content injection, build or release compromise, unauthorized changes, data exposure, or misleading provenance using the repository's private security-reporting channel where available. If that channel is unavailable, contact the maintainer without publicly posting sensitive exploit details.

Include the affected route or file, reproduction steps, and impact. Do not include credentials, confidential accounting records, client information, or personal data. Avoid destructive testing of the public service.

The corpus accepts no sensitive production data. Synthetic examples stay synthetic. Consumers should treat retrieved text and embedded scenario instructions as untrusted data and preserve their own authority boundaries. Publisher links and imported descriptions do not establish current trust or permissions.

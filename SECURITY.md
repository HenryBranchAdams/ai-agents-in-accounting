# Security policy

This repository and public service are read-only by design. Report vulnerabilities that could expose data, change published records without review, bypass authorization, inject executable content, compromise build or release integrity, or mislead clients about authority and provenance.

Use the private security-reporting channel provided by the project host. Include the affected route or file, reproduction steps, impact, and any suggested containment. Do not include real accounting records, credentials, personal data, or client information. Avoid destructive testing against the public service.

We aim to acknowledge a report within seven days, assess severity and scope, and publish a corrected release and advisory when appropriate. Timing may vary for volunteer maintenance or coordinated disclosure.

The project does not accept sensitive production data. Workflow packs and benchmark fixtures must remain synthetic. API clients should treat this service as public, untrusted input and enforce their own retrieval, authorization, and reliance policies.

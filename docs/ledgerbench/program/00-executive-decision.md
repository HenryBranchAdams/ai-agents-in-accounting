# LedgerBench
## A first-class benchmark program for accounting agents

**Working title:** LedgerBench  
**Document:** Program blueprint and operating constitution  
**Version:** 0.1  
**Date:** August 24, 2026

---

## Executive decision

LedgerBench should not begin as a dataset, leaderboard, or collection of accounting questions.

It should begin as a **measurement institution** whose purpose is to answer:

> Can an AI system complete consequential accounting work to a standard that a qualified professional would accept, under realistic evidence, time, access, and authority constraints, with measurable reliability and review burden?

The program should produce three distinct products:

1. **Capability benchmarks** — comparative evaluations of what systems can accomplish.
2. **Conformance suites** — pass/fail tests of required behavior, interfaces, and control boundaries.
3. **Field-utility studies** — controlled measurements of human productivity, reviewer effort, and deployment outcomes.

These products must not be collapsed into one score. A competitive benchmark asks which system performs better. A conformance program asks whether a system satisfies specified requirements. A field study asks whether a system creates value in a particular operating context. Each requires a different methodology.

The benchmark should evaluate the **complete candidate system**—model, agent policy, context, tools, retrieval, memory, code, and configuration—not a model name in isolation. Model comparisons are possible only in a tightly standardized division.

The program should be living, versioned, statistically explicit, resistant to contamination, independently governed, and able to retire or replace tasks as systems improve.

# Domain documentation

This repository uses a single-context domain-documentation layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant decisions under `docs/adr/` when they exist.
- Proceed silently when either location is absent; create domain documentation only when a real modeling or decision need emerges.

## Vocabulary

Use the project glossary and canonical record vocabulary in issue titles, acceptance criteria, tests, and implementation documentation. Do not substitute generic AI terminology for the project's accounting-native concepts.

## Decisions

Surface any conflict with an existing architecture decision rather than silently overriding it. Record new durable decisions under `docs/adr/` when implementation resolves a meaningful architectural choice.

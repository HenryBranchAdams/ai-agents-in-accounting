# Drafts, candidates and finalized editions

Use `npm run edition -- plan` before preparing a content edition. Changes to rendering, documentation, tooling or styles alone need no edition. The plan compares current catalog/corpus/coverage inputs with the commit that incorporated the existing immutable release. It includes new, unstaged data. Keep edits in canonical current records; do not manually create numbered history for each wording change.

`npm run edition -- prepare YYYY-MM-DD.N` captures all source inputs and real Git history into `outputs/editions/<candidate-id>/source`. The candidate identity includes the source digest, Git revision, prospective edition, preparation date and Node version. Preparation installs the lockfile independently using the npm cache, synchronizes current version headers, regenerates mappings, validates records, and uses the existing snapshot and release generators. It preserves reviewed dates, assessment content, independently versioned classifications, rights and all existing history bytes. Inspect its `prepared.json` changes and `prepare.log`.

Missing cached dependencies are a recoverable preparation failure. Run `npm ci` in the source checkout using the same npm cache configuration, then repeat preparation. Previous failed attempts remain in `.failed-<time>` directories. Identical successful preparation returns the same candidate and validates its captured source digest. Corrected source inputs create a different candidate ID; provide the previously reserved ID as the third argument to explicitly supersede it while keeping the same prospective version:

```
npm run edition -- prepare YYYY-MM-DD.N PREVIOUS_CANDIDATE_ID
```

This only replaces the local reservation, not finalized source. Candidates and logs are excluded from source exports. No candidate receipt grants publication authority, and preparing a candidate does not establish editorial, professional or human acceptance. Source-dependent editorial reviews must be performed again when their inputs change.

Run the full working-copy checks against this already prepared capture with:

```
npm run check:working -- --candidate outputs/editions/CANDIDATE_ID/source
```

This reuses the captured inputs and installed lockfile dependencies, runs the complete lint/build/test contract in that independent directory, and binds the receipt to its actual input digest. It remains nonpublishable. The ordinary working-copy capture does not silently allocate an edition; changed content that needs coherent release exports should use this deliberate preparation path first.

## Deliberate finalization

After reviewing the candidate, run `npm run edition -- finalize CANDIDATE_ID` in the unchanged editing checkout. This is the finalization boundary: it deliberately adds the prepared immutable release and coverage snapshot to canonical source and synchronizes the generated headers/indexes. Review and commit these files before the full committed verification and CI gates. Publication still requires the authenticated successful main-CI artifact.

All original inputs, generated bytes, source revision and the edition reservation are checked before the first canonical write. An exclusive operation lock prevents two preparers/finalizers from claiming the same local edition. Each individual file is atomically replaced. A durable journal and reservation mark an interrupted multi-file promotion; verification refuses that state. Repeat the same finalization command to finish it. Resume accepts only the recorded original or prepared bytes, refuses intervening edits, and never restores files over another editor's work. Repeating completed finalization before committing is idempotent.

A process killed without cleanup can leave `outputs/editions/operation.lock`. Inspect its recorded PID and the finalization journal. Only after confirming that owner is no longer running, move the stale lock aside, retain it with the failed-attempt evidence, then resume the same command. Do not remove an active owner's lock. An unexpected temporary promotion file is retained evidence; inspect it before retrying.

Once finalized, corrections use a subsequent edition after committing the finalized source. Do not delete, relabel or overwrite that edition to hide a failed check. Existing historical releases and snapshots remain byte-identical. Preliminary corrections before finalization reuse the prospective version with a new candidate identity and invalidate affected verification evidence.

`npm run preview` remains a draft reading surface with publication paths disabled. Full candidate verification and production publication are separate gates. This command does not silently perform either gate.

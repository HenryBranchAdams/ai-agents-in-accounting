# Private Sites MCP connection

The current private adapter retrieves an immutable qualified Git corpus through four owner-only tools: describe, search, get and context. It uses sealed compressed runtime data and the existing application factory with retrieval contract 1.4.1. Git remains canonical; public citation links may serve an older edition. The private derivative preserves rights, provenance, dates and unknowns and stores no publisher full text or private financial records.

## Legacy public API adapter

The original adapter uses the existing public Accounting Agents API for four read-only tools: describe, search, get and context. It stores no corpus records, publisher full text or private financial information. `scripts/private-mcp/server.mjs` adapts the existing remote client behavior without importing its local-corpus fallback. The installed MCP SDK supplies stateless initialization, discovery, calls and output validation in Cloudflare Workers.

The preserved upstream contract was retrieved from the public `/schemas/agent.schema.json` on October 2, 2026. It is schema **1.2.0**, served with corpus **2026-09-22.2** at that observation. GitHub main is newer. Results retain the actual served edition, citations, rights, provenance, review limits and omission accounting unchanged. A different upstream retrieval schema fails output validation until the adapter is explicitly updated and tested. An optional corpus-version pin fails on mismatch. Invalid calendar dates are rejected by the adapter, but the older public corpus's applicability and omission semantics remain its own; this connection does not claim main's newer historical-applicability behavior.

Sites owns OAuth and the owner-only access policy. Data-bearing requests additionally require the platform's trusted authenticated-user ID and verified email matching the `OWNER_EMAIL` runtime value. Missing identity returns 401; a different owner, missing owner configuration or missing verified email returns 403. A platform service credential does not manufacture user identity. Static MCP initialization and tool schemas disclose no private data and make no upstream request. Never expose this Worker outside the Sites trusted-header boundary or widen the Site audience to avoid a failed call.

The adapter only requests the fixed public origin's four GET endpoints, refuses redirects, limits requests to 15 seconds and responses to 2 MB, and preserves structured remote errors. MCP POST requests are bounded to 64 KiB and reject batches. No arbitrary publisher fetching, writes, corpus cache or account integration is provided.

Source publication remains separate from the existing public corpus Site. Prepare a new private Site checkout with `server.mjs`, `upstream-contract.json`, `build.mjs`, the MIT notice, a package declaring the existing SDK 2.0.0 and esbuild 0.28.2 versions, and its own `.openai/hosting.json` with the requested `mcp` capability. Set the runtime owner from that Site's verified sole-owner access response; keep it out of source. Run the Sites workflow in that checkout and publish privately using its provisioned App/plugin. Do not alter the canonical repository's public Site identity, create a separate App, or configure local MCP credentials.

Original adapter changes are MIT licensed. Project-created annotations remain CC BY 4.0 and factual metadata CC0; original publisher rights remain separate. Forwarding the existing public research responses does not grant permission to reproduce the linked standards or other publisher material. Record-level restrictions and unknown rights remain visible.

`tests/private-sites-mcp.test.mjs` exercises actual SDK discovery and calls, owner access failures with zero upstream traffic, fixed-origin forwarding, response parity, calendar rejection, version/schema mismatch and size/error limits. `node scripts/private-mcp/build.mjs outputs/private-mcp-build` builds only the adapter and records its input inventory; the build refuses local corpus/client imports. Runtime QA and private deployment verification remain separate from these local checks.

## Pinned private edition

When the public Site serves an older edition, `current-server.mjs` provides the same four tools against an immutable private deployment derivative. Git remains the sole canonical corpus. This derivative uses the qualified application's `createApplication` factory and its existing compressed runtime data, with retrieval contract 1.4.1. It does not request the public API, fetch publishers, use a network fallback, add storage bindings, or expose corpus pages, runtime assets, historical downloads, source archives or release-import routes.

The integration owner must authenticate the exact successful CI artifact and validate its packaged file inventory before packaging. Local package metadata is an input check, not proof of hosted CI authenticity. Run:

```sh
node scripts/private-mcp/build-current.mjs /absolute/qualified/ci-release-package outputs/private-current EXACT_40_CHARACTER_SOURCE_SHA
```

The consumed package contains `release-package.json`, `evidence/qualification.json`, `evidence/release-meta.json`, `storage/manifest.json`, `storage/objects/`, and `application/dist/server/`. Each used file must match the root package inventory. The packager reconstructs the stored `/downloads/agent.schema.json` and only the `/_runtime/data/` logical files; it parses verified server modules with esbuild to select the unique `createApplication` export. The packager checks the exact source SHA, release mode, edition, storage manifest and object hashes, reconstructed runtime hashes and data keys. It reuses known module imports through esbuild; it never evaluates JavaScript strings. The sealed Worker module graph, complete project licenses/attribution, third-party notices and a local private qualification report are produced. The Worker graph must remain below 64 MiB; compressed data and module hashes are recorded in that report. Complete project licenses, attribution and third-party permission texts are embedded in a preserved `/*! ... */` comment in `server/index.js`; its final size and hash include those bytes. Companion notice files remain available for local inspection. Deploy `server/` through the separately controlled private Sites workflow; the report is local evidence, not a public static asset. Never give the private derivative a corpus asset directory or widen access to work around identity errors.

The existing trusted authenticated-user ID and owner-email check remains the boundary for every data-bearing MCP request. Static initialization and tool discovery disclose schemas only and do not load private modules or decompress data. After owner authorization, the runtime verifies the exact compressed asset inventory and hashes, bounds JSON expansion to each recorded size and checks its SHA-256 data key, initializes the qualified factory, and checks its schema, corpus edition and record count before retaining the immutable application. Missing data, corrupted hashes or a differing edition fail closed. Concurrent authorized cold calls share one initialization promise; a failed initialization clears it for a later retry. Only the four exact local agent GET routes can be invoked. An explicit corpus-version mismatch and impossible calendar date fail before initialization. Requests, runtime owner values and credentials are never retained with the application.

Tool results preserve the canonical structured output unchanged. MCP result `_meta.connector_meta` separately reports the private source SHA, corpus version, schema version, counts and asset/factory hashes. Citation and publisher URLs retain their original values. Canonical public links can serve an older edition; the initialization instructions and landing page state that limitation. Packaging and deployment do not establish publisher re-verification, source currency, professional review or expanded reuse rights.

`tests/private-current-package.test.mjs` uses disposable artifact fixtures to test package bounds, source pins and corrupted/missing objects. `tests/private-current-mcp.test.mjs` runs after the primary build and checks owner gating, static discovery, private route rejection, version/date failures, corrupt/missing runtime data, the exact local GET operations, and search/get/context/describe parity with the existing implementation, including canonical dates, provenance, rights and omissions. Full `npm run check`, hosted CI, private deployment and authenticated plugin verification remain separate integration-owner gates.

The 64 MiB module check is independent of runtime memory and startup limits. Local Node observations do not establish native Worker support. Cold-start and concurrent-call verification in the target provider remains a deployment gate.

The canonical browser search index initializes only after a valid browser search. Agent retrieval retains its existing separate index and passage materialization; an agent-only private request does not create a second normalized copy of every record for unused browser searches. Search algorithms, citations, ranking, filters and results are unchanged.

The canonical browser search index initializes only when browser search is used. Agent search retains compact facets and numeric tokens, and derives the same normalized body text for each eligible record during a query. Search results retain a lazy passage accessor rather than materializing all matched records through an object spread. This reduces retained memory while preserving ranking, snippets, citations, cursors and omission behavior; textual queries perform more per-query work. Empty queries avoid unused body and passage ranking. Local parity and timing observations do not establish native Worker memory support: qualify the exact final derivative and verify an authenticated data-bearing call before reporting that the private edition works.

# Private Sites MCP connection

The owner-private Site uses the existing public Accounting Agents API for four read-only tools: describe, search, get and context. It stores no corpus records, publisher full text or private financial information. `scripts/private-mcp/server.mjs` adapts the existing remote client behavior without importing its local-corpus fallback. The installed MCP SDK supplies stateless initialization, discovery, calls and output validation in Cloudflare Workers.

The preserved upstream contract was retrieved from the public `/schemas/agent.schema.json` on October 2, 2026. It is schema **1.2.0**, served with corpus **2026-09-22.2** at that observation. GitHub main is newer. Results retain the actual served edition, citations, rights, provenance, review limits and omission accounting unchanged. A different upstream retrieval schema fails output validation until the adapter is explicitly updated and tested. An optional corpus-version pin fails on mismatch. Invalid calendar dates are rejected by the adapter, but the older public corpus's applicability and omission semantics remain its own; this connection does not claim main's newer historical-applicability behavior.

Sites owns OAuth and the owner-only access policy. Data-bearing requests additionally require the platform's trusted authenticated-user ID and verified email matching the `OWNER_EMAIL` runtime value. Missing identity returns 401; a different owner, missing owner configuration or missing verified email returns 403. A platform service credential does not manufacture user identity. Static MCP initialization and tool schemas disclose no private data and make no upstream request. Never expose this Worker outside the Sites trusted-header boundary or widen the Site audience to avoid a failed call.

The adapter only requests the fixed public origin's four GET endpoints, refuses redirects, limits requests to 15 seconds and responses to 2 MB, and preserves structured remote errors. MCP POST requests are bounded to 64 KiB and reject batches. No arbitrary publisher fetching, writes, corpus cache or account integration is provided.

Source publication remains separate from the existing public corpus Site. Prepare a new private Site checkout with `server.mjs`, `upstream-contract.json`, `build.mjs`, the MIT notice, a package declaring the existing SDK 2.0.0 and esbuild 0.28.2 versions, and its own `.openai/hosting.json` with the requested `mcp` capability. Set the runtime owner from that Site's verified sole-owner access response; keep it out of source. Run the Sites workflow in that checkout and publish privately using its provisioned App/plugin. Do not alter the canonical repository's public Site identity, create a separate App, or configure local MCP credentials.

Original adapter changes are MIT licensed. Project-created annotations remain CC BY 4.0 and factual metadata CC0; original publisher rights remain separate. Forwarding the existing public research responses does not grant permission to reproduce the linked standards or other publisher material. Record-level restrictions and unknown rights remain visible.

`tests/private-sites-mcp.test.mjs` exercises actual SDK discovery and calls, owner access failures with zero upstream traffic, fixed-origin forwarding, response parity, calendar rejection, version/schema mismatch and size/error limits. `node scripts/private-mcp/build.mjs outputs/private-mcp-build` builds only the adapter and records its input inventory; the build refuses local corpus/client imports. Runtime QA and private deployment verification remain separate from these local checks.
